# Дашборд стажировок МГТС

Прототип ИИ-системы с аналитическим дашбордом для финала кейс-чемпионата ПАО «МГТС» **«Код города»** (26 ноября 2026, направление «ИИ и автоматизация бизнес-процессов»).

Система автоматически собирает ежемесячные анкеты стажёров и наставников МГТС за 6 контрольных периодов (месяцы 1–6), связывает ответы по `ID стажёра` и периоду, отслеживает статус сдачи, считает динамику и парные расхождения, разбирает комментарии через **GigaChat-2-Pro** (с дословной сверкой цитат и офлайн-словарём как резервом) и формирует понятный светофор и следующий шаг для HR.

## Внешние анкеты (Яндекс Формы по структуре МГТС)

- **Анкета стажёра:** https://forms.yandex.ru/u/6b07e04d6f1ca439809e2e52/
- **Анкета наставника:** https://forms.yandex.ru/u/6b07e6672c4f895672dbc8f9/

Новые ответы приходят письмом в почтовый ящик интеграции и автоматически забираются дашбордом по IMAP (`core/mail.py`), связываясь с историей стажёра без ручного экспорта.

## Как запустить локально

Выполняйте команды из каталога `dashboard`. Исторический датасет МГТС (`data/mgts/`: `СТ-001`..`СТ-005`, 6 месяцев, 60 анкет) и карта вопросов (`survey/questions_mgts.csv`) подключены по умолчанию и подгружаются автоматически при первом открытии:

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откроется страница в браузере с уже загруженным датасетом МГТС. Без ключа нейросети всё работает: комментарии в этом случае разбирает встроенный словарь.

Чтобы подключить нейросеть, скопируйте `.env.example` в `.env`, впишите ключ и проверьте:

```
python scripts/check_llm.py
```

Для локальной проверки задайте отдельную временную базу и журнал webhook (PowerShell):

```
$checkDir = Join-Path ([IO.Path]::GetTempPath()) ("mgts-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $checkDir | Out-Null
$env:DB_PATH = Join-Path $checkDir "test.db"
$env:WEBHOOK_LOG_PATH = Join-Path $checkDir "webhook.jsonl"
$env:PYTHON_DOTENV_DISABLED = "1"
python -m pytest -q --basetemp (Join-Path $checkDir "pytest") tests
```

## Как устроено

```
сервис анкет -> загрузка (core/ingest.py) -> база SQLite -> расчёты (core/metrics.py) -> app.py
                                                  |
                                    разбор комментариев (core/comments.py)
```

- `survey/questions.csv` говорит, какая колонка выгрузки какому вопросу соответствует, какая у него шкала
  и в какую сторону он задан. Если анкета поменялась, правим только этот файл. Перед импортом дашборд проверяет
  сопоставление и показывает, какие строки и ответы будут пропущены. Сами анкеты лежат в `survey/anketa.md`.
- `core/ingest.py` читает выгрузку (CSV, XLSX, JSON или ссылку на CSV) и раскладывает её по одной строке на ответ.
  У каждого ответа есть свой ключ, поэтому повторная загрузка не создаёт дублей. Исправление принимается, если его
  время отправки строго новее сохранённого; запоздалый старый ответ пропускается. Если ответы различаются, но время
  отсутствует, не разбирается или совпадает, импорт сообщает о конфликте для ручной проверки.
- `survey/yandex_fields.csv` связывает технические ID вопросов опубликованных Яндекс Форм с колонками выше.
  При замене формы нужно сверить её ID вопросов и обновить эту таблицу. Контрольные ответы обеих ролей
  25.11.2026 дошли до почты в формате JSON; живой забор через IMAP (7/7 писем, 0 ошибок) и импорт в SQLite
  проверены на отдельной базе.
- `webhook.py` принимает анкеты по одной, если сервис анкет умеет слать запрос при новом ответе.
- `core/comments.py` отправляет комментарии в нейросеть пачками и получает по каждому тональность, темы и сигналы
  («хочет уйти», «перегруз» и т.д.). Ответ нейросети проверяется: значения только из наших списков,
  цитата должна реально быть в тексте. Фамилии перед отправкой заменяются на «[имя]».
- `core/metrics.py` считает средние по месяцам, eNPS и риск по каждому стажёру.
- `core/playbook.py` по причинам риска выбирает одно действие для HR и подставляет имена в готовый текст сообщения.
  Действий десять, они записаны в коде. Нейросеть сообщения не пишет: HR должен заранее знать, что ему предложат,
  и в тексте не должно оказаться цитат из анкеты.
- `core/effect.py` считает эффект в рублях. Все входные числа это допущения, их вводят на странице «Эффект».
  В коде нет ни одной цифры компании.
- `app.py` это интерфейс. Главный экран это лента «кому нужно внимание на этой неделе»: причина, цитата,
  действие, сообщение и кнопка «Сделано». Дальше карточка стажёра, пробная анкета и загрузка данных.

## Если анкета другая

Для выгрузки правится `survey/questions.csv`. Для почтового JSON новой Яндекс Формы также нужно обновить
`survey/yandex_fields.csv`. Одна строка `questions.csv` это одна колонка выгрузки:

- `column`: название колонки в выгрузке. Регистр, запятые и лишние пробелы не важны.
- `role`: чей вопрос, `intern` или `mentor`. Для общих полей `any`.
- `kind`: `scale` оценка, `nps` рекомендация от 0 до 10, `text` комментарий, `meta` служебное поле, `time` время заполнения.
- `min` и `max`: границы шкалы. Для `scale` пусто значит от 1 до 5, для `nps` — от 0 до 10.
  eNPS допускает шкалу 0–10 или 1–10, потому что считает ответы 0–6 и 9–10.
- `reverse`: 1, если высокая оценка это плохо («нагрузка слишком высокая»).
- `avg`: 1, если вопрос входит в среднюю оценку месяца.
- `block`: тема вопроса. По ней подбирается действие для HR. Особые значения: `нагрузка`, `наставник`, `задачи`,
  `развитие`, `будущее` (хочет ли остаться), `штат` (наставник рекомендует в штат), `время наставника`.
- у служебных полей `id` должны быть `intern`, `dept`, `mentor`, `month`, `ts`.

При загрузке оценки типа `scale` переводятся в шкалу от 1 до 5, где 5 всегда хорошо. Значения вне заданной шкалы
не используются в расчётах. Период анкеты — месяцы с 1 по 6. Для импорта каждой роли нужна хотя бы одна
оценочная колонка, включённая в среднее: без неё не получится показать динамику стажёра или наставника.
После смены файла сопоставления очистите базу в разделе «Данные».
Там же показаны неизвестные колонки и число пропущенных строк/значений.

Для тренировки есть второй набор: те же истории стажёров, но шкала 1-10, обратные вопросы, Excel, дубли строк
и ФИО в разном написании. Запуск в PowerShell:

```
python scripts/make_demo_data_v2.py
$env:QUESTIONS_CSV="survey/questions_v2.csv"; $env:DEMO_DIR="data/demo_v2"; $env:DB_PATH="data/v2.db"; streamlit run app.py
```

## Почему так

Риск считаем правилами с баллами, а не моделью машинного обучения. На одного стажёра максимум шесть анкет,
обучать модель не на чем. Правила можно показать HR и объяснить каждое срабатывание. Таблица правил есть
на странице «Обзор», пороги лежат в `core/config.py`.

Нейросеть используем только там, где без неё никак, то есть для текста. Цифры она не считает.
Так меньше шансов, что она что-то выдумает.

Для красной зоны нужны 50 баллов и признаки как минимум двух типов. Сигнал о намерении уйти
с дословной цитатой сам поднимает приоритет до красной зоны.

Анкету помечаем как формальную, если есть хотя бы два признака: однообразные оценки, короткий или пустой
комментарий, быстрое заполнение. Оценки участвуют в расчётах, а пометка помогает HR сверить вывод.

Если нейросеть недоступна, работает словарь ключевых слов. Он грубее, но дашборд не падает без интернета.

Streamlit выбрали, потому что на финале на всё три часа. Он позволяет собрать рабочий интерфейс на одном Python.

## Проверка

В демо-данных 24 стажёра и 5 месяцев. Семь стажёров заложены с проблемами: перегруз, нет помощи наставника,
мало задач, перестал отвечать, вежливые оценки при желании уйти, недовольный наставник, один плохой месяц.
Тесты проверяют, что первые шесть попадают в красную зону, седьмой в жёлтую, а из остальных никто не красный.

Для сравнения: простое правило «средняя оценка ниже 3» на этих же данных не находит ни одного из шести.
Наши правила находят троих на третьем месяце и всех шестерых на четвёртом. Данные мы придумали сами,
поэтому это проверка логики, а не доказательство точности на настоящих стажёрах.

## Что проверено и ограничения пилота

- **Исторические данные МГТС (`СТ-001`..`СТ-005`, 6 месяцев, 60 анкет):** загружены через `survey/questions_mgts.csv`; система выявляет кризис `СТ-003` (месяцы 1–3), парный разрыв `СТ-005` по «Задачам» (`2.0` vs `4.0`) и скрытый перегруз `СТ-004` на 4-м месяце (`2/5` при средней `4.4/5`).
- **Живые интеграции:** приём писем обеих ролей из Яндекс Форм через IMAP и разбор 86 комментариев через **GigaChat-2-Pro** проверены 26.11.2026 (включая срабатывание антигаллюцинационного фильтра, отклонившего 1 неточную цитату модели).
- **Автотесты:** 52/52 автотеста (`pytest`) покрывают загрузку, дубли/версии, парные расхождения, статус сдачи, парсер писем Яндекс Форм, антигаллюцинацию и расчёт экономики.
- **Границы пилота (для внедрения в промконтур МГТС):** подключение корпоративного SSO и ролевой модели (152-ФЗ), развёртывание БД и локальной/контурной LLM внутри инфраструктуры МГТС, калибровка ставок калькулятора на фактических данных HR.
