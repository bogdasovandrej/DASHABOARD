# Профильный вебинар «ИИ и автоматизация процессов», 13.11.2026

Расшифровано автоматически по звуку записи (модель Whisper small), возможны ошибки в словах.
Кейс рассказывала Юля, бизнес-аналитик МГТС; она будет наставником направления на финале.

## Что будет на финале (время в записи)

- Два датасета: две таблицы Excel с ответами стажёров и ответами наставников за один период. «Они там друг друга оценивают» (29:45).
- 5 стажёров, 5 наставников, 6 ежемесячных опросов, у каждого ответ за каждый месяц (29:58).
- Один наставник — один стажёр (45:56, ответ на вопрос из чата).
- Данные синтетические (38:43).
- Структуру анкет дадут. Анкету нужно повторить в Google Forms, Яндекс Формах или похожем сервисе (31:00).
- Ответы из формы должны по API попадать в ваш сервис и наполнять дашборд. Нужен веб-интерфейс, чтобы загрузить новые данные: в следующий раз стажёры и наставники заполнят вашу форму, и ответ сам появится в дашборде (31:12–31:39).
- Собирать в базу или обрабатывать Excel напрямую — «для нас непринципиально» (30:52).
- Главное показать: динамику, расхождения, сигналы и исходный код. Нужен работающий прототип, локальный запуск устроит (31:43–31:58).
- «Технически задачка не особо сложная, она сложная бизнесово: сами сигналы нужно определить вам» (32:02).
- Оценка презентации строится на том, как вы объясните: «этот показатель очень важный, потому что раз-два-три» (32:42).
- Можно любые инструменты, платные и бесплатные, вайб-кодинг тоже (30:25, 36:07).
- Конструктора дашбордов в требованиях нет; решайте сами, нужен ли он бизнесу (41:22).
- Структуру данных заранее не дают, чтобы кейс решался за три часа (43:06).
- Принести свой готовый продукт и доработать — можно, если в итоге он соответствует требованиям; структуру анкет и данных нужно сохранить (43:11–43:46).

## Что ещё сказали (про ИИ в МГТС)

- МГТС из-за регуляторных требований не использует внешние модели вроде Claude и GPT для внутренних данных. У компании свои видеокарты и open-source модели внутри контура, данные не уходят наружу (09:25–10:02).
- Перед тем как брать задачу в работу, команда всегда считает потенциальный эффект: сколько денег сэкономит или заработает (26:08).
- ИИ нужен там, где действие нельзя описать формулой и нужно «подумать». Если задачу решает скрипт или классический метод, ИИ не нужен (24:21, 18:27).
- Сначала автоматизируют один сценарий, проверяют вручную, потом добавляют следующий (28:12).

## Что это значит для нашего проекта

| Факт с вебинара | Что меняется у нас |
|---|---|
| 5 стажёров, а не 24–30 | Сравнение «с потоком», eNPS и доли по потоку почти бессмысленны на пяти людях. Лента на 5–7 человек — это почти весь поток |
| Один наставник — один стажёр | Таблица «нагрузка наставников» и находка «у Белова трое стажёров» на финале не сработают |
| Друг друга оценивают | Расхождение стажёр ↔ наставник — одно из трёх главных требований. Стоит сравнивать по парным вопросам |
| Ответы из формы по API в дашборд | **Не закрыто.** У личных Яндекс Форм нет API, автоматической передачи сейчас нет |
| Нужен веб-интерфейс загрузки | Есть: раздел «Данные» |
| Показать исходный код | Код должен быть понятен и показан на защите |
| Свои модели в контуре | Довод для защиты: модель меняется одной строкой на open-source внутри МГТС |
| Считают эффект до начала работ | Страница «Эффект» в тему |
